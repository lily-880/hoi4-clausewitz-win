## 总司令循环
- `live_trial.py tick`：一拍 = 采集 → decide → 契约校验 → 执行已验证命令 → 让游戏走 N 小时 → 暂停。
  - 预检或预演被拒属于确定的「不行」：记录下来，继续下一条。
  - Post 之后没确认的属于不确定：停下整拍，不重试。
- `calling/decide_v1.py`：在 v0 告警和态势说明之上，加规则 R1「增援被以多打少的防守」。只用引擎读出的邻接，只在 allow_write 且地理范围已设定时下令。
- 回执账本：`research/claude_live/ledger.jsonl`，每条动作一行；accepted 只在观察到真实效果后才记 true。

## 事故与修正：游戏被留在运行状态
第 3 项观察时，我把「继续 → 最多 140 次采样 → 暂停」做成一个后台任务，然后在它还在跑的时候结束了本轮回复。用户发现游戏无人看管地在跑（实际从 01-04 跑到 01-09 16:00），手动指出后我立即暂停并停掉后台任务。期间部队状态全部正常，没有战斗或损失发生在受测部队上。

根因：
1. 暂停只是 shell 链条最后一步，任务被杀或崩溃就不会执行；
2. 我在游戏运行时结束了回合。

修正：
- 时钟只在一个 Python 进程内由 `watch --run` / `tick --hours` 打开，`finally` 中必定暂停；
- 单次运行有 180 秒真实时间硬上限；
- 一律前台执行；
- 规则：游戏未确认暂停前不结束回合。

修正后两次实跑均以 pause=1 结束：一次触发 180 秒上限，一次在到达时结束。
