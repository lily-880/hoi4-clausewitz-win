把陆军总司令看成每个游戏节拍调用一次的 decide(input) → output。本页是与《陆军总司令权限宪章》配套的完整输入、输出字段、类型与格式。引擎暂时读不到的字段标成可选，不能编造。

> **定稿日期 2026-11-06（Asia/Shanghai）**
> 现行状态。配套权限宪章；输入里可选字段表示引擎读不到就省略，不能猜测邻接、路径或包围。allow_write 为 false 时只能出告警和说明。

## 函数形态

```
decide(input: GeneralissimoInput) -> GeneralissimoOutput
```

它不自己去点科技、改征兵或开工厂。玩家方针和当前陆战可见世界作为参数喂进来；输出是对游戏的写入命令、给玩家的告警、态势说明，以及可选的高层意图（必须能编译成原子命令）。

```text
meta     节拍元信息 ─┐                 ┌─> orders   写入命令
policy   玩家方针   ─┤                 ├─> alerts   告警
world    世界快照   ─┼──> decide() ────┼─> brief    态势说明
feedback 上一拍回执 ─┘                 └─> intents  高层意图
```

| | |
|---|---|
| 输入四块 | meta、policy、world、feedback |
| 输出四块 | orders、alerts、brief、intents |
| 写入前提 | meta.allow_write 为 true；否则 orders 必须为空数组 |
| 空输出 | 一拍可以没有任何命令，只有告警和说明，表示维持现状或在等闸门 |

（原页此处链接：陆军总司令权限宪章 · 资料库 · 2026-11-05）

## 共享类型

| 类型 | 格式 | 说明 |
|---|---|---|
| ProvinceId | int | 引擎省份 ID，例如 7980 |
| UnitId | int | 师或可识别陆军实体的内部编号，例如 1838 |
| ArmyId | int | 集团军编号 |
| ArmyGroupId | int | 集团军群编号 |
| PlanId | int | 前线 / 进攻线 / 驻防等计划对象 |
| LeaderId | int | 将领编号 |
| CombatId | int | 一场陆战的编号 |
| CountryRef | { index: int, tag?: string } | index 是引擎国家序号（如玩家 15）；tag 是三字母代号（如 ETH），解不出就省略 |
| GameTime | { year, month, day, hour } | 全部为 int，游戏内日历时间，例如 1936-01-05 13 时 |
| Subject | { unit_ids?, army_ids?, army_group_ids? } | 命令作用对象，至少填一类 ID 数组 |
| Relation | 枚举 | self \| ally \| enemy \| neutral \| subject \| overlord \| unknown |
| OrderType | 枚举 | idle \| move \| strategic_redeploy \| attack \| support_attack \| retreat \| garrison \| training \| exercise \| unknown |
| PlanType | 枚举 | frontline \| offensive_line \| garrison \| area_defense |
| Speed | 枚举 | pause \| 1x（不允许 5x） |

## 输入契约

GeneralissimoInput 含 meta、policy、world、feedback 四块。world 是当前节拍的陆战可见快照。

### 节拍元信息 meta

| 字段 | 类型 | 说明 |
|---|---|---|
| game_time | GameTime | 游戏内日历时间 |
| player_country | CountryRef | 玩家控制的国家 |
| speed | Speed | 输入约束：仅 pause 或 1x |
| allow_write | bool | 默认 false；为 false 时函数只能观察和告警 |
| geography_scope | null \| { kind: global } \| { kind: theater, province_ids: int[] } | 现行宪章为 null（范围待定），不能自行假定全球或仅某战区 |

### 玩家方针 policy

| 字段 | 类型 | 说明 |
|---|---|---|
| stance | 枚举 | preserve_force \| hold_line \| annihilate \| economize_manpower \| custom |
| instructions | string | 自然语言总方针原文 |

stance 未给时，按「保部队优先，再寻歼灭机会」处理。

### 己方陆军 world.own_units

Unit[]。每个 Unit：

| 字段 | 类型 | 说明 |
|---|---|---|
| unit_id | UnitId | 师或可识别陆军实体 |
| name? | string | 显示名 |
| province_id | ProvinceId | 当前所在省份 |
| owner | CountryRef | 所属国家 |
| relation_to_player | Relation | 己方清单里主要是 self / ally / subject / overlord |
| template? | { template_id: int, name?: string, battalions?: { type: string, count: int }[], combat_width?: number } | 编制，在可读范围内 |
| organization? | number | 引擎原始组织度，不做额外换算 |
| strength? | { manpower?: int, current?: number, max?: number, equipment_ratio?: number } | equipment_ratio 为 0.0–1.0 |
| supply? | { in_supply: bool, ratio?: number, isolated?: bool } | 补给状态属必有感知 |
| in_combat | bool | 是否在作战 |
| combat_id? | CombatId | 指向 world.combats |
| order | { type: OrderType, target_province_ids: int[], path_province_ids: int[], eta?: { hours?: number, progress?: number } } | 当前任务；path 按途经顺序；eta 读不到就省略 |
| formation? | { army_id?: ArmyId, army_group_id?: ArmyGroupId } | 所属编成 |
| leader_id? | LeaderId | 直接挂在师上的将领（若有） |

### 可见其他陆部队 world.visible_units

结构与 Unit 相同，粒度以战争迷雾和引擎可读范围为限。看不见的部队不出现在数组里。规模可用粗粒度（师数、估测兵力）。

| 字段 | 类型 | 说明 |
|---|---|---|
| relation_to_player | Relation | enemy \| neutral \| ally \| unknown 等 |
| visibility | { spotted: bool, confidence?: number } | confidence 为 0.0–1.0 |

| 字段 | 类型 | 说明 |
|---|---|---|

### 缺装与缺人 world.shortages

不做扩编，但必须能发现缺口。equipment_type 用引擎内部名（如 infantry_equipment），数量用整数。

| 字段 | 类型 | 说明 |
|---|---|---|
| equipment[] | { equipment_type: string, stockpile?: int, demanded?: int, deficit?: int, affected_unit_ids?: int[], affected_plan_ids?: int[] } | 装备库存与需求差 |
| manpower | { available?: int, needed?: int, deficit?: int, affected_unit_ids?: int[], front_cannot_hold?: bool } | 人力缺口 |
| missing_divisions? | { plan_id?: PlanId, province_ids?: int[], needed_estimate?: int, reason: string } | 现有兵力撑不住某段战线 |

### 上一拍回执 feedback

宪章要求「下达 → 观察 → 失败则改下法」，所以上一拍结果也是本拍输入。

| 字段 | 类型 | 说明 |
|---|---|---|
| last_orders[] | { order_seq: int, type: OrderType \| PlanCommandType, subject_ids: int[], target_province_ids?: int[], plan_id?: int, accepted: bool, error?: string } | 上一拍每条命令的落地结果 |
| ticks_since_issue? | int | 用于判断命令未生效 |

PlanCommandType：create_frontline | create_offensive_line | create_garrison | assign_to_plan | reassign_unit | create_army | create_army_group | assign_leader | use_leader_ability | train | exercise。

### 不进入该函数的数据

- 外交与和谈、贸易、科研树、国策、征兵及其他法案
- 工厂与产线、海空军兵力与任务、雷达与防空建设、情报网操作
- 存档内容、作弊开关
- 补给状态要读；铁路换轨、枢纽修复、陆运优先级的写入属 v2，现行不作为可执行输入

## 输出契约

GeneralissimoOutput 含 orders（对游戏的写入）、alerts、brief（不写游戏）、intents（解释用，必须能落地为原子命令）。

### 闸门与公共字段

meta.allow_write 为 false 时，写入命令必须是空数组，只能出告警和说明。每条写入命令都带：

| 字段 | 类型 | 说明 |
|---|---|---|
| order_seq | int | 本拍内序号，对照下一拍 feedback.last_orders |
| subject | Subject | unit_ids / army_ids / army_group_ids 至少一类 |
| reason? | string | 决策理由（保部队、堵口、合围闭合等） |
| replaces_order_seqs? | int[] | 声明本条是在改下法或取代未生效命令 |

### 机动与交战 orders.maneuver

| type | 主要字段 | 说明 |
|---|---|---|
| move | target_province_ids: int[]；path_province_ids?: int[] | 普通移动。多点表示途经或分散终点 |
| strategic_redeploy | 同上 | 战略机动 |
| attack | target_province_ids: int[] | 进攻 |
| support_attack | target_province_ids: int[]；supported_unit_ids?: int[] | 支援进攻；可指明支援哪几支正在打的部队 |
| retreat | to_province_ids?: int[] | 一开始就授权。无明确后撤地则表示就地脱离或按引擎默认后撤 |
| cancel | cancel_scope: current_movement \| current_combat_order \| all_queued | 取消行军或当前运动类命令 |

集结、分流、堵口、合围闭合不是新的 type，而是多条上述命令的组合；若要表达意图，放到 intents，并在 expands_to_order_seqs 里指出编译结果。

### 集团军与集团军群 orders.formation

这些是编成写入，不含扩军。unit_ids 必须是已存在的己方陆军实体；任何「按某模板新练一个师」都属越权，无效。

| type | 主要字段 | 说明 |
|---|---|---|
| create_army | new_ref: string；name?: string；unit_ids: int[]；leader_id?: int；parent_army_group_id? 或 parent_army_group_ref? | 新建集团军。new_ref 供本拍后续命令引用尚未落地的编号 |
| modify_army | army_id: int；name?；add_unit_ids?；remove_unit_ids?；parent_army_group_id?: int \| null | 调入/调出师；null 表示移出集团军群。调出不解散师本身 |
| disband_army | army_id: int；reassign_unit_ids_to_army_id?: int | 拆掉集团军结构；师回到未编组或指定去处 |
| create_army_group | new_ref: string；name?: string；army_ids: int[]；leader_id?: int | 新建集团军群 |
| modify_army_group | army_group_id: int；name?；add_army_ids?；remove_army_ids? | 调整下属集团军 |
| disband_army_group | army_group_id: int；keep_armies: bool | keep_armies 应为 true；只拆群结构，不能借解散把师删掉 |
| assign_units | unit_ids: int[]；to_army_id: int；from_army_id?: int | 把师调入集团军 |
| unassign_units | unit_ids: int[]；from_army_id: int | 把师调出集团军，仍留在地图上 |

### 将领任免与战地技能 orders.leaders

| type | 主要字段 | 说明 |
|---|---|---|
| assign_leader | leader_id: int；post: { kind: army \| army_group, id: int } 或 { kind: army_ref \| army_group_ref, ref: string } | 任命；ref 可指向本拍刚创建的结构 |
| unassign_leader | leader_id: int；post 同上 | 免职或调离 |
| reassign_leader | leader_id: int；from_post；to_post | 从 A 岗位改任 B，等价于免职加任命，写成一条以免中间空窗 |
| use_leader_ability | leader_id: int；ability: string；target?: { province_ids?, unit_ids?, combat_id? } | 使用与陆战直接相关的将领战地技能或精神；ability 为引擎技能名或已证明的内部 id |

不能输出：改陆军学说树、点将领学说、用技能变相改国家法案。

### 前线、进攻线与驻防 orders.plans

| type | 主要字段 | 说明 |
|---|---|---|
| create_frontline | new_ref；vertex_province_ids: int[]；assigned_army_ids?；assigned_unit_ids?；execute?: bool | 折线控制点按绘制顺序；execute 默认 true |
| update_frontline | plan_id 或 plan_ref；vertex_province_ids?；assigned_army_ids?；assigned_unit_ids? | 改前线走向或换防部队 |
| delete_frontline | plan_id: int | 删除前线 |
| create_offensive_line | new_ref；vertex_province_ids；axis_province_ids?；parent_frontline_id? 或 parent_frontline_ref?；编成指派；execute? | axis 是推进轴；若引擎需要则挂在某条前线下 |
| update_offensive_line | 同更新前线，外加 axis_province_ids? | 改进攻线或推进轴 |
| delete_offensive_line | plan_id: int | 删除进攻线 |
| create_garrison / create_area_defense | new_ref；province_ids: int[]；编成指派；execute? | 只能用现有部队填线 |
| update_garrison / update_area_defense | plan_id 或 plan_ref；province_ids?；编成指派 | 改防区或换防部队 |
| delete_garrison / delete_area_defense | plan_id: int | 删除驻防或区域防御 |
| set_plan_execution | plan_id: int；executing: bool | 开始执行或暂停计划 |
| assign_to_plan | plan_id: int；army_ids?；unit_ids? | 把部队绑到计划 |
| unassign_from_plan | 同上 | 从计划解绑 |

不能输出：为填线而新建民兵或守备师，或改驻防模板。

### 训练与演习 orders.tasks

宪章默认允许，作为任务结构的一部分。指已有部队的训练任务，不是出门新师。若日后收回，只需把这三类标成无效。

| type | 主要字段 | 说明 |
|---|---|---|
| train | subject；until?: { organization?: number, experience?: number } | 训练；until 可省略，按引擎默认 |
| exercise | subject；until? | 演习 |
| cancel_task | subject | 取消训练或演习 |

### 高层意图 intents

解释用，必须能落地。没有 expands_to_order_seqs 的意图视为无效。

| 字段 | 类型 | 说明 |
|---|---|---|
| intent_id | string | 本拍意图编号 |
| kind | 枚举 | concentrate \| split \| seal_pocket \| close_encirclement \| fall_back_to_line \| hold_line \| exploit \| relieve_encircled \| custom |
| province_ids? | int[] | 相关地理 |
| subject | Subject | 涉及部队或编成 |
| expands_to_order_seqs | int[] | 必须指向本拍真实的机动、计划或编成命令 |
| notes? | string | 补充说明 |

### 告警 alerts

必有义务，不等于扩编权。告警不得附带越权写入。大捷大败、被包、缺装缺人应同时出现在 alerts 里，不只写在 brief 里。

| 字段 | 类型 | 说明 |
|---|---|---|
| alert_id | string | 告警编号 |
| severity | 枚举 | info \| watch \| high \| critical |
| kind | 枚举 | 见下表 |
| message | string | 给玩家看的一句说明 |
| payload | 随 kind 变化 | 见下表 |
| suggested_player_action? | string | 只能建议玩家去做总司令没权限的事 |

| kind | payload | 用途 |
|---|---|---|
| equipment_shortage | { equipment_type, deficit?, stockpile?, demanded?, affected_unit_ids?, affected_plan_ids? } | 缺装备 |
| manpower_shortage | { available?, needed?, deficit?, affected_unit_ids? } | 缺人力 |
| missing_divisions | { plan_id?, province_ids?, needed_estimate?, reason } | 某段战线现有兵力无法维持 |
| major_victory / major_defeat | { combat_id?, province_id?, casualties? } | 大捷或大败 |
| encircled / encirclement_imminent | { unit_ids, province_ids } | 被包围或即将被包 |
| plan_failed | { plan_id?, failed_order_seqs?, error? } | 计划无法执行或反复下达失败 |
| insufficient_permission | { need: conscription \| production \| template \| doctrine \| focus \| diplomacy \| navy \| air \| other, detail } | 必须由玩家处理 |

### 态势说明 brief

写给玩家，不写进游戏。不是日报的强制版式，但宪章要求能把态势和决策说清楚。

| 字段 | 类型 | 说明 |
|---|---|---|
| game_time | GameTime | 与输入相同的游戏时间 |
| summary | string | 本拍在干什么 |
| stance_applied | string 或 stance 枚举 | 实际采用的方针；输入缺省时会是保部队优先 |
| fronts? | { plan_id: int, assessment: string }[] | 各条战线评估 |
| risks? | string[] | 风险 |
| next_watch? | string[] | 下一拍重点盯什么 |

### 不能作为输出的东西

- 新建师、部署未出门的师、改师模板、加营、设装备生产优先、调工厂
- 点学说、国策、征兵法及其他法案
- 宣战媾和、外交、贸易
- 海空军指挥；雷达与防空建设；情报网操作
- 铁路换轨、枢纽修复、陆运优先级写入（v2 未授权）
- 改游戏规则、作弊、5x、擅自读写档
- 地理范围未定时，假设自己获得了全球或某战区的排他指挥权

## 运行周期

上文是类型字典（函数能看见、能下达的全集），不是每小时全量快照。周期按游戏内时钟计算：新的一小时、日切、每 7 个游戏日的日初、每月 1 日日初。每条注明为必送（到点就传）、按需可送（有事才写）或不送（留给更慢的层，除非被事件打断）。

### 总原则

- 事件优先于日历：被包、组织崩盘、命令被拒、省份易手等不等下一个整点
- 输入用上一拍快照加脏数据，不重复发没变的部队、省份和计划
- 输出允许为空：没有新命令就只回空数组，这是正常情况
- 慢层的事不要塞进每小时；快层的事不要拖到每周或每月（例如撤退不能等月报）
- 静态地图与玩家方针不按点循环，只在变更时再送

### 事件打断（优先于日历）

触发：战斗开始或结束、部队抵达、命令未生效或被拒、被包或即将被包、组织崩盘、断补给、看守省份易手、停火投降傀儡化、玩家改方针或 allow_write。

| 方向 | 项目 | 规则 |
|---|---|---|
| 输入 | game_time、speed、allow_write | 必送 |
| 输入 | 涉事部队的位置、组织度、兵力、补给、战斗与当前命令，相关省份与邻接（若已缓存则只送脏值） | 必送 |
| 输入 | 相关 combat、crisis、feedback.last_orders | 必送 |
| 输出 | maneuver：尤其 retreat、cancel、attack、support_attack、move | 按需可送 |
| 输出 | use_leader_ability（战地技能） | 按需可送 |
| 输出 | alerts：encircled、encirclement_imminent、major_victory、major_defeat、plan_failed | 必送（确实发生时） |
| 输出 | 集团军编成、大规模改前线/进攻线 | 不送（除非事件本身就是计划失效、必须当场收缩） |

### 每小时

每个游戏内小时的心跳。只看热点部队和进行中的事，不重发全军名册、不改编成、不重画战线。

| 方向 | 项目 | 规则 |
|---|---|---|
| 输入 | meta.game_time、speed、allow_write | 必送 |
| 输入 | 己方热点部队：正在战斗、行军、撤退，或本小时位置/组织度/兵力/补给/命令有变。字段为 province_id、organization、strength、supply、in_combat、combat_id、order | 必送 |
| 输入 | 可见敌军：新发现，或位置、规模有变 | 必送 |
| 输入 | 进行中的 combats，以及本小时结束的战斗与战损 | 必送 |
| 输入 | crises 当前清单（无即为空） | 必送 |
| 输入 | feedback：上一小时已下达、结果尚未落地的命令 | 必送 |
| 输入 | 全部师的编制、集团军名册、将领档案、计划折线、全图省份、缺装缺人全表 | 不送 |
| 输出 | orders.maneuver：move、strategic_redeploy、attack、support_attack、retreat、cancel | 按需可送 |
| 输出 | use_leader_ability | 按需可送 |
| 输出 | alerts：encircled、encirclement_imminent、major_victory、major_defeat（本小时发生的） | 必送（有则必报，无则不发） |
| 输出 | brief、缺装缺人告警、编成、任免、新建或重画前线/进攻线/驻防 | 不送 |

### 每日

每个游戏日日切时做一次日常诊断。用来补全非热点部队、看缺口和计划是否在执行，并给玩家一份日报。

| 方向 | 项目 | 规则 |
|---|---|---|
| 输入 | 己方非热点部队的日刷：province_id、organization、strength、supply、formation、order.type（防止长期只看热点而漂） | 必送 |
| 输入 | 迷雾内可见陆部队点名 | 必送 |
| 输入 | shortages：equipment、manpower、missing_divisions | 必送 |
| 输入 | plans：plan_id、type、executing、status、assigned_army_ids / assigned_unit_ids（折线未变则不重传 vertex） | 必送 |
| 输入 | wars 与 front_invalidated | 必送 |
| 输入 | 计划沿线与部队所在省的 controller / owner 变更 | 必送 |
| 输出 | brief：game_time、summary、stance_applied、fronts、risks、next_watch | 必送 |
| 输出 | alerts：equipment_shortage、manpower_shortage、missing_divisions、insufficient_permission（仍存在才报） | 必送（有则必报） |
| 输出 | orders.tasks：train、exercise、cancel_task | 按需可送 |
| 输出 | orders.plans：set_plan_execution、assign_to_plan、unassign_from_plan；仅当日评估要求时才 update 折线 | 按需可送 |
| 输出 | maneuver（与每小时相同，日初也可下） | 按需可送 |
| 输出 | create/disband 集团军或集团军群、换将、新建前线或进攻线 | 不送（留给每周，除非事件强制） |

### 每周

每 7 个游戏日的日初，与当日日报一起做作战结构检讨：编成、任免、战线走向与进攻轴。

| 方向 | 项目 | 规则 |
|---|---|---|
| 输入 | 完整编成：army_groups、armies、各集团军的 unit_ids | 必送 |
| 输入 | leaders：岗位、四维、特性（供换将决策） | 必送 |
| 输入 | plans 全折线：vertex_province_ids、axis_province_ids | 必送 |
| 输入 | 相关省份的 infrastructure、fort_level、victory_points（terrain 与 neighbors 若已静态缓存则不重发） | 必送 |
| 输入 | 本周相对上周的缺口趋势 | 必送 |
| 输出 | orders.formation：create / modify / disband 集团军与集团军群；assign_units / unassign_units | 按需可送 |
| 输出 | orders.leaders：assign_leader、unassign_leader、reassign_leader | 按需可送 |
| 输出 | orders.plans：create / update / delete 前线、进攻线、驻防或区域防御 | 按需可送 |
| 输出 | intents（concentrate、hold_line、close_encirclement 等作战意图，必须能编译成当拍原子命令） | 按需可送 |

### 每月

每个游戏月 1 日日初，做战区级检视与给玩家的月度交代。不把撤退或解围拖到这一层。

| 方向 | 项目 | 规则 |
|---|---|---|
| 输入 | 相关战区的省份快照：归属、基建、要塞、胜利点（地理范围待定前，至少覆盖有部队或有计划的省份） | 必送 |
| 输入 | 完整 wars：交战、停火、投降、傀儡 | 必送 |
| 输入 | 数周以来的缺装、缺人、缺师趋势 | 必送 |
| 输入 | policy.stance 与 instructions（若玩家本月未改，可标 unchanged，不必重复长文） | 必送 |
| 输出 | 战区级的计划重画、集团军群重构（仍走每周那套 formation / plans 命令） | 按需可送 |
| 输出 | brief 的月度段：〔原件在此截断，后续内容缺失〕 | 必送 |
